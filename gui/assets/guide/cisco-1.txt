# CLI basics
## The command modes
The switch has levels, called modes. The prompt tells you which one you are in, and each mode allows different commands.
| Prompt | Mode | How to get there | What it is for |
|---|---|---|---|
| `Switch>` | User EXEC | Log in | Looking only: a few `show` commands, `ping` |
| `Switch#` | Privileged EXEC | `enable` | All `show` commands, `copy`, `reload`; the way into configuration |
| `Switch(config)#` | Global configuration | `configure terminal` | Settings of the whole switch |
| `Switch(config-if)#` | Interface configuration | `interface <name>` | Settings of one port |
| `Switch(config-line)#` | Line configuration | `line console 0`, `line vty 0 15` | Console and remote login |
| `Switch(config-vlan)#` | VLAN configuration | `vlan <id>` | A VLAN's name and options |
| `switch:` or `rommon 1 >` | Boot loader | Interrupt the boot | Recovery only |

[Switch>] enable
Goes to privileged EXEC mode. It asks for the enable password if one is set.

[Switch#] configure terminal
Goes to global configuration mode. Short form: `conf t`.

[Switch(config)#] interface gigabitEthernet 1/0/1
Goes to the configuration of one port. Short form: `int g1/0/1`.

[Switch(config-if)#] exit
Goes back one level.

[Switch(config-if)#] end
Goes straight back to privileged EXEC from any configuration level. Ctrl+Z does the same.

[Switch#] disable
Goes back from privileged to user EXEC.

~ A `show` command only works in EXEC modes. From a configuration mode, put `do` in front: `do show vlan brief`.

## Getting help
Type `?` anywhere to see what can come next. It is the fastest way to learn the CLI.
- `?` alone lists the commands of the current mode.
- `sh?` lists the commands that start with "sh". `show ip ?` lists what can follow `show ip`.
- Tab completes a word. You can also shorten a word as long as it is unique: `sh run` is `show running-config`, `conf t` is `configure terminal`, `sh ip int br` is `show ip interface brief`.
| Message | Meaning |
|---|---|
| `% Incomplete command.` | The command needs more words: add `?` to see which |
| `% Invalid input detected at '^' marker.` | A typo, or the command does not exist in this mode: the `^` points at it |
| `% Ambiguous command:` | The shortened word matches several commands: type more letters |

## Keyboard shortcuts
| Keys | What they do |
|---|---|
| Up, Down (or Ctrl+P, Ctrl+N) | Earlier and later commands |
| Ctrl+A, Ctrl+E | Start and end of the line |
| Ctrl+B, Ctrl+F | One character back or forward |
| Esc then B, Esc then F | One word back or forward |
| Ctrl+U | Delete the whole line |
| Ctrl+W | Delete the word before the cursor |
| Ctrl+K | Delete from the cursor to the end |
| Ctrl+Z | Leave configuration: back to privileged EXEC |
| Ctrl+C | Cancel a configuration dialog or a pasted command |
| Ctrl+Shift+6, then X | Stop a running `ping` or `traceroute` |
| Space, Enter, Q at `--More--` | Next page, next line, quit |

## Undo, defaults and filters
[Switch(config-if)#] no shutdown
Putting `no` in front of a command removes it or does the opposite.

[Switch(config)#] default interface gigabitEthernet 1/0/1
Sets a port back to its factory settings: it removes the description, VLAN and everything else configured on it.

[Switch#] show running-config | section interface
Shows only the parts that match. Other filters: `| include vlan` lines with the word, `| exclude` lines without it, `| begin line vty` from the first match to the end, `| count` how many lines.

[Switch#] show running-config | include hostname|snmp|logging
Shows only lines with one of several words (a `|` inside the pattern means "or").

[Switch#] show running-config interface gigabitEthernet 1/0/5
Shows the configuration of one port only.

[Switch#] terminal length 0
Stops the `--More--` pause for this session. Use `terminal length 24` to bring it back.

[Switch#] show history
Lists the last commands you typed.

# First setup of a new switch
## Name it and secure it
Connect to the console (see Start here → Connect to the console), press Enter and type the following.

[Switch>] enable
+ configure terminal
Enters configuration mode.

[Switch(config)#] hostname SW1
Names the switch: the prompt changes to `SW1(config)#`.

[SW1(config)#] no ip domain-lookup
Stops the switch trying to look up a mistyped command as a host name, which causes a long "Translating…" wait.

[SW1(config)#] enable algorithm-type scrypt secret <password>
Sets the password for privileged mode, stored as a strong hash (type 9) on current IOS XE. On older software use `enable secret <password>` (type 5, MD5). Without a type, newer IOS XE converts the secret to type 9 by itself.
! Never use `enable password`: it stores the password in plain text.

[SW1(config)#] username admin privilege 15 algorithm-type scrypt secret <password>
Creates a local administrator for SSH and console login.

[SW1(config)#] service password-encryption
Lightly scrambles any plain-text passwords left in the configuration (type 7). It is easily reversed: it only hides them from someone looking over your shoulder.

[SW1(config)#] banner motd # Authorized access only. #
Shows a message before login. The first character after `motd` is the delimiter and ends the message.

## Console and remote lines
[SW1(config)#] line console 0
+ logging synchronous
+ exec-timeout 10 0
+ login local
+ exit
`logging synchronous` stops log messages from cutting into what you type. `exec-timeout 10 0` logs out after 10 idle minutes (0 means never: avoid it). `login local` asks for a local user name and password.

[SW1(config)#] line vty 0 15
+ login local
+ transport input ssh
+ exec-timeout 10 0
+ exit
Settings for remote logins (the "virtual terminals"). `transport input ssh` allows SSH only, which switches Telnet off.
~ Some switches have `line vty 0 4` and `line vty 5 15` as separate blocks. `0 15` configures them together.

## The management address
A Layer 2 switch is reached through a VLAN interface, called an SVI.

[SW1(config)#] vlan 99
+ name Management
+ exit
Creates the management VLAN first.

[SW1(config)#] interface vlan 99
+ ip address 192.168.99.2 255.255.255.0
+ no shutdown
+ exit
Gives the switch an address in that VLAN.

[SW1(config)#] ip default-gateway 192.168.99.1
The gateway the switch itself uses to reach other networks (on a Layer 2 switch).
! The VLAN interface stays down until the VLAN exists and at least one active port or trunk carries it. If `show ip interface brief` shows it as down/down, check the VLAN and the ports.

[SW1#] ping 192.168.99.1
Checks the way to the gateway. Success shows `!!!!!`.

## Turn on SSH
1. Give the switch a domain name: `ip domain-name lab.local`.
2. Generate an RSA key: `crypto key generate rsa modulus 2048`. From IOS XE 17.10 the key must be at least 2048 bits.
3. Use SSH version 2 only: `ip ssh version 2`. The default (1.99) is a compatibility mode.
4. Allow only SSH on the lines: `transport input ssh` and `login local` under `line vty 0 15`.

[SW1(config)#] ip domain-name lab.local
+ crypto key generate rsa modulus 2048
+ ip ssh version 2
Prepares SSH. The key takes a few seconds to generate.
! If a key already exists, the switch asks whether to replace it: answer no unless you want new keys (clients will then warn about a changed key).

[SW1#] show ip ssh
Shows whether SSH is on, its version and timeouts. `show ssh` lists current sessions.

## Set the clock
[SW1#] clock set 14:30:00 22 October 2026
Sets the time by hand (privileged EXEC). Better: use NTP (see IP services).

[SW1(config)#] clock timezone CET 1
Names the time zone and its offset from UTC.

[SW1#] show clock
Shows the time. Wrong times make logs hard to use.

## Save your work
[SW1#] copy running-config startup-config
Saves the configuration that is running now, so that it is still there after a reload. Short form: `copy run start`. `write memory` (`wr`) does the same.
~ The running-config is the active configuration in memory: a change works at once but is lost when the power goes. The startup-config is the saved copy that loads at boot.

## A complete starting configuration
Copy this, change the names and passwords, and paste it in parts (see Start here → Safe habits).

[Switch#] configure terminal
+ hostname SW1
+ no ip domain-lookup
+ ip domain-name lab.local
+ enable algorithm-type scrypt secret CHANGE-ME
+ username admin privilege 15 algorithm-type scrypt secret CHANGE-ME
+ service timestamps log datetime msec
+ service timestamps debug datetime msec
+ line console 0
+ logging synchronous
+ exec-timeout 10 0
+ login local
+ exit
+ vlan 99
+ name Management
+ exit
+ interface vlan 99
+ ip address 192.168.99.2 255.255.255.0
+ no shutdown
+ exit
+ ip default-gateway 192.168.99.1
+ line vty 0 15
+ login local
+ transport input ssh
+ exec-timeout 10 0
+ end
Paste this part first. Then paste `crypto key generate rsa modulus 2048` and `ip ssh version 2` separately (after `configure terminal`), because generating the key pauses and can swallow the lines that follow. Finally `copy running-config startup-config`.

# Looking around: the daily show commands
## What is this switch?
[SW1#] show version
Model, serial number, software version, how long it has been running, why it last restarted and the configuration register.

[SW1#] show inventory
Model and serial numbers of the switch, stack members, power supplies and transceivers.

[SW1#] show running-config
The configuration that is running. Long: use `| section` or `| include` (see CLI basics).

[SW1#] show startup-config
The saved configuration. If it differs from the running one, you have unsaved changes.

[SW1#] show flash:
The files in flash memory: the software image, `vlan.dat`, configuration backups. `dir flash:` shows the same with sizes.

## Interfaces at a glance
[SW1#] show ip interface brief
One line per interface with its address and state. The most used command of all.
> Interface              IP-Address      OK? Method Status                Protocol
> Vlan1                  unassigned      YES unset  administratively down down
> Vlan99                 192.168.99.2    YES manual up                    up
> GigabitEthernet1/0/1   unassigned      YES unset  up                    up
> GigabitEthernet1/0/2   unassigned      YES unset  down                  down

| Status / Protocol | Meaning |
|---|---|
| up / up | Working |
| up / down | The port has a link but Layer 2 is not working (or a VLAN interface has no active port) |
| down / down | No link: cable, other end off, wrong speed or duplex |
| administratively down / down | Someone shut it down: `no shutdown` brings it up |

[SW1#] show interfaces status
One line per port with its name, state, VLAN, duplex, speed and type: the best view of a switch's ports.
> Port      Name               Status       Vlan       Duplex  Speed Type
> Gi1/0/1   Printer            connected    10         a-full  a-1000 10/100/1000BaseTX
> Gi1/0/2                      notconnect   1            auto    auto 10/100/1000BaseTX
> Gi1/0/3   Old-PC             err-disabled 10           auto    auto 10/100/1000BaseTX
> Gi1/0/4                      disabled     999          auto    auto 10/100/1000BaseTX
> Gi1/0/48  To-CORE            connected    trunk       a-full  a-1000 10/100/1000BaseTX
`a-full` and `a-1000` mean negotiated automatically. `notconnect` is no link, `disabled` is shut down by hand, `err-disabled` was shut down by a protection feature.

[SW1#] show interfaces gigabitEthernet 1/0/1
All details of one port: state, speed, duplex, rates and error counters.

[SW1#] show interfaces trunk
The trunk ports, their native VLAN and which VLANs they carry.

[SW1#] show vlan brief
The VLANs and the access ports in each. Trunk ports are not listed.
> VLAN Name                             Status    Ports
> ---- -------------------------------- --------- -------------------------------
> 1    default                          active    Gi1/0/2, Gi1/0/3
> 10   Sales                            active    Gi1/0/1
> 99   Management                       active
> 1002 fddi-default                     act/unsup

## Who is connected?
[SW1#] show mac address-table
Which MAC address the switch learned on which port and VLAN. Narrow it down: `show mac address-table interface g1/0/1`, `show mac address-table vlan 10`, `show mac address-table address 0050.7966.6801`, `show mac address-table dynamic`.

[SW1#] show ip arp
The IP-to-MAC table of the Layer 3 interfaces. Together with the MAC table it finds the port of any address.

[SW1#] show cdp neighbors detail
The Cisco devices attached to each port: name, model, address, port. `show cdp neighbors` is the short list.

[SW1#] show lldp neighbors detail
The same through LLDP, the standard that works with other makes (see IP services to turn it on).

## Is everything healthy?
[SW1#] show logging
The log: link changes, STP events, configuration changes, errors. See Troubleshooting for what the messages mean.

[SW1#] show spanning-tree summary
Spanning tree mode and the number of ports in each state per VLAN.

[SW1#] show etherchannel summary
The bundles of links and whether their members are working.

[SW1#] show ip route
The routing table (Layer 3 switches and routers).

[SW1#] show processes cpu sorted | exclude 0.00
The busiest processes. High CPU can point to a loop, a flood or a broken feature.

[SW1#] show environment all
Temperature, fans and power supplies (the exact command depends on the model).

[SW1#] show power inline
PoE: how much power each port gives and the total budget.

[SW1#] show users
Who is logged in to the switch now.

[SW1#] show tech-support
Dumps nearly everything. Very long: send it to Cisco support, or save it from the terminal log.

# Interfaces
## Choosing ports
Ports are named by speed and position: `GigabitEthernet1/0/1` (Gi1/0/1) is stack member 1, module 0, port 1. Prefixes: Fa FastEthernet, Gi GigabitEthernet, Te TenGigabitEthernet, Twe TwentyFiveGigE, Hu HundredGigE. Older switches use two numbers: Gi0/1.

[SW1(config)#] interface gigabitEthernet 1/0/1
Selects one port.

[SW1(config)#] interface range gigabitEthernet 1/0/1 - 24
Selects several ports, so one set of commands applies to all. The spaces around the hyphen are required. Combine ranges with commas: `interface range g1/0/1 - 4 , g1/0/10`.

## Describe, shut down, set speed
[SW1(config-if)#] description Printer 2nd floor
A note that shows in `show interfaces status`: always describe uplinks and servers.

[SW1(config-if)#] shutdown
Switches the port off. `no shutdown` switches it on.

[SW1(config-if)#] speed 100
+ duplex full
Fixes speed and duplex. Set both ends the same way, or leave both on `auto`. One end fixed and the other on auto causes a duplex mismatch.
! Gigabit copper links need auto-negotiation: do not fix their speed unless the other end requires it.

## Counters and errors
[SW1#] show interfaces gigabitEthernet 1/0/1 | include error|CRC|collision|duplex|rate
Picks the interesting lines of a long output.

[SW1#] show interfaces counters errors
The error counters of all ports in one table.

[SW1#] clear counters gigabitEthernet 1/0/1
Sets the counters to zero, so that you can see whether errors keep growing.
| Counter | Usually means |
|---|---|
| CRC, input errors | A bad cable or connector, interference, or a duplex mismatch |
| Runts | Frames that are too short: a duplex mismatch or a faulty device |
| Giants | Frames that are too big: a wrong MTU or a faulty device |
| Late collisions | A duplex mismatch (a half-duplex end on a full-duplex link) |
| Output drops | Congestion: more traffic than the port can send |

## Err-disabled ports
A protection feature (port security, BPDU guard, loop detection, link flap and others) can shut a port down. It shows as `err-disabled`.

[SW1#] show interfaces status err-disabled
Lists the ports that are err-disabled and the reason.

[SW1#] show errdisable recovery
Which causes recover by themselves, and how long it takes.

[SW1(config-if)#] shutdown
+ no shutdown
Brings the port back after you fixed the cause. If you do not fix it, the port goes down again.

[SW1(config)#] errdisable recovery cause bpduguard
+ errdisable recovery interval 300
Recovers ports shut down for that cause after 300 seconds. Other causes: `psecure-violation`, `link-flap`, `loopback`, `udld`. Use it with care: it hides the problem while it repeats.

## Cables, optics and PoE
[SW1#] test cable-diagnostics tdr interface gigabitEthernet 1/0/1
Starts a cable test on copper ports (not on every model). A short while later: `show cable-diagnostics tdr interface gigabitEthernet 1/0/1` shows open or short pairs and the length.

[SW1#] show interfaces transceiver detail
The light levels and temperature of optical modules, where supported. Low receive power points to a dirty connector or a bad fibre.

[SW1(config-if)#] power inline auto
PoE settings of a port: `auto` (default), `never` (off), `static max 15400` (reserve milliwatts).

# VLANs
## What a VLAN is
A VLAN is a separate Layer 2 network inside the switch. Devices in one VLAN do not see the broadcasts of another: to talk to each other, traffic must pass a router or a Layer 3 switch.
| VLAN IDs | Use |
|---|---|
| 0 and 4095 | Reserved: not usable |
| 1 | The default VLAN: every port starts in it; it cannot be deleted or renamed |
| 2 to 1001 | Normal range: kept in `vlan.dat` |
| 1002 to 1005 | Reserved for old FDDI and Token Ring: always present |
| 1006 to 4094 | Extended range: kept in the running configuration |
~ Keep user traffic and the management address out of VLAN 1. Use a VLAN of your own for management and park unused ports in an unused VLAN.

## Create VLANs
[SW1(config)#] vlan 10
+ name Sales
+ exit
Creates VLAN 10 and names it. Several at once: `vlan 10,20,30`, but the names have to be set one by one.

[SW1#] show vlan brief
Lists the VLANs. A VLAN that you configured but that is missing here was not created.

## Access ports
[SW1(config)#] interface gigabitEthernet 1/0/5
+ switchport mode access
+ switchport access vlan 10
+ spanning-tree portfast edge
Makes the port an access port in VLAN 10 and lets it come up at once (see Spanning tree). `portfast edge` is the new name; older software uses `spanning-tree portfast`.

[SW1(config)#] interface range gigabitEthernet 1/0/1 - 24
+ switchport mode access
+ switchport access vlan 10
The same for a whole group of ports.

[SW1(config-if)#] switchport voice vlan 150
Adds a second VLAN for an IP phone on the same port: the phone's traffic is tagged, the PC behind it is not.

[SW1#] show interfaces gigabitEthernet 1/0/5 switchport
How a port is set: administrative and operational mode, access VLAN, voice VLAN, trunk settings.
~ If you give a port a VLAN that does not exist, some software creates it automatically and some leaves the port inactive: check `show vlan brief`.

## Change and delete
[SW1(config)#] no vlan 10
Deletes VLAN 10.
! The ports of a deleted VLAN do not move to VLAN 1: they become inactive and carry nothing. Move the ports first.

[SW1#] delete flash:vlan.dat
Erases the stored VLAN database. Together with `write erase` and a reload it resets an old switch completely.

# Trunks
## Trunk configuration
A trunk carries several VLANs between switches (or to a router or access point). Each frame gets a 802.1Q tag with its VLAN ID, except the frames of the native VLAN, which are sent without one.

[SW1(config)#] interface gigabitEthernet 1/0/48
+ switchport mode trunk
+ switchport trunk native vlan 999
+ switchport trunk allowed vlan 10,20,99
+ switchport nonegotiate
+ description To-CORE
Makes a trunk with a native VLAN that nothing else uses, carrying only the VLANs it needs, with DTP negotiation off.

[SW1(config-if)#] switchport trunk encapsulation dot1q
Needed on older switches that can also do ISL (such as the Catalyst 3560 and 3750), before `switchport mode trunk`. On most switches the command does not exist: they only use 802.1Q.

[SW1(config-if)#] switchport trunk allowed vlan add 30
Adds VLAN 30 to the list. Also: `remove 30`, `except 30` (all except), `all`, `none`.
! `switchport trunk allowed vlan 10,20` replaces the whole list. Forgetting `add` is a classic cause of lost connectivity.

[SW1#] show interfaces trunk
Four tables: the ports and their mode, the allowed VLANs, the allowed VLANs that exist, and the VLANs forwarding in spanning tree.
> Port        Mode         Encapsulation  Status        Native vlan
> Gi1/0/48    on           802.1q         trunking      999
>
> Port        Vlans allowed on trunk
> Gi1/0/48    10,20,99
>
> Port        Vlans allowed and active in management domain
> Gi1/0/48    10,20,99
>
> Port        Vlans in spanning tree forwarding state and not pruned
> Gi1/0/48    10,20,99
A VLAN missing from the last table is not passing traffic: check that it exists on both switches and is not blocked by spanning tree.

## DTP: the automatic trunk
Cisco switches can negotiate a trunk with the Dynamic Trunking Protocol. The default on most Catalysts is `dynamic auto`.
| This port | Other port | Result |
|---|---|---|
| dynamic auto | dynamic auto | Access (no trunk) |
| dynamic auto | dynamic desirable or trunk | Trunk |
| dynamic desirable | dynamic auto, dynamic desirable or trunk | Trunk |
| trunk | trunk, dynamic desirable or dynamic auto | Trunk |
| access | anything | Access |
! Do not leave trunks to negotiate: it is a security risk (a host can ask for a trunk). Set `switchport mode trunk` with `switchport nonegotiate` on both ends, and `switchport mode access` on every other port.

## Native VLAN mismatch
The native VLAN must be the same at both ends of a trunk. If it differs, traffic leaks between VLANs and the switch logs warnings.
> %CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on GigabitEthernet1/0/48 (1), with SW2 GigabitEthernet0/1 (99).
> %SPANTREE-2-RECV_PVID_ERR: Received BPDU with inconsistent peer vlan id 99 on GigabitEthernet1/0/48 VLAN1.
Fix it with `switchport trunk native vlan <id>` on the side that is wrong.

# Routing between VLANs
## A Layer 3 switch with SVIs
A Layer 3 switch can route between its VLANs itself. Each VLAN gets an address on the switch (an SVI), which the hosts use as their default gateway.

[SW1(config)#] ip routing
Turns routing on (a Layer 3 switch is a Layer 2 switch until you do this).

[SW1(config)#] interface vlan 10
+ ip address 192.168.10.1 255.255.255.0
+ no shutdown
+ exit
Gives VLAN 10 its gateway address. Hosts in VLAN 10 use 192.168.10.1 as their gateway.

[SW1(config)#] interface vlan 20
+ ip address 192.168.20.1 255.255.255.0
+ no shutdown
Same for VLAN 20: now hosts in VLAN 10 and VLAN 20 can reach each other.

[SW1#] show ip route
Shows the connected networks as `C` entries, one per SVI.

[SW1#] show ip interface brief
Each VLAN interface must be up/up. An SVI is down when its VLAN does not exist or has no active port.

## Router on a stick
With a router and a switch, one cable between them carries all VLANs: the switch port is a trunk and the router has a sub-interface per VLAN.

[Router(config)#] interface gigabitEthernet 0/0/1
+ no shutdown
+ exit
Turns the physical interface on. It carries no address itself.

[Router(config)#] interface gigabitEthernet 0/0/1.10
+ encapsulation dot1Q 10
+ ip address 192.168.10.1 255.255.255.0
Creates the sub-interface for VLAN 10. The number after the dot is just a name: matching it to the VLAN ID keeps things clear.

[Router(config)#] interface gigabitEthernet 0/0/1.99
+ encapsulation dot1Q 99 native
+ ip address 192.168.99.1 255.255.255.0
Sub-interface for the native VLAN (its frames are untagged).

[SW1(config)#] interface gigabitEthernet 1/0/48
+ switchport mode trunk
The switch side of the cable: a trunk that allows the VLANs.

## A routed port
[SW1(config)#] interface gigabitEthernet 1/0/47
+ no switchport
+ ip address 10.0.0.2 255.255.255.252
Turns a switch port into a Layer 3 port with its own address, for example a link to a router or another Layer 3 switch.

## When VLANs cannot reach each other
- The hosts have the SVI address as their gateway, and the right mask.
- Both SVIs are up/up, and `ip routing` is on.
- The VLAN exists on every switch it crosses, and every trunk between carries it.
- No ACL blocks the traffic (see Access control lists).
- `ping` from the switch to a host (`ping 192.168.10.50`) shows whether the switch sees the host. `show mac address-table vlan 10` and `show ip arp` show whether it learned the host.
